# 赛事直播模块实施计划

## Context

省级中小学足球系统（d:\ball，绿地，仅空 git 仓库）需建设"赛事直播模块"，属用户负责的门户域三部分之一（另两部分：新闻首页、运动员端，后续另行规划）。

模块范围（来自功能设计 Excel）：
- 公众侧：直播列表页、直播观看页（图文时间轴 + 实时比分 + 双方阵容 + 第三方直播链接）
- 管理侧：比赛/对阵/裁判员录入、进球与判罚（含换人）事件 CRUD、赛事文件上传（签到表/记录集签字确认表/裁判员报告书）、直播链接管理、球员人脸核验（先 mock）

技术栈（已批准）：Laravel 10+/PHP 8.2 + MySQL 8 + Redis + Sanctum；Vue3 + TS + Element Plus + Pinia。必须遵守两份团队手册（后端分层/统一响应/响应码/三通道日志/事务与性能规范；前端目录/组件拆分/接口自测/字典与 composables 规范），要点见 `project_memory.md`。

## 关键技术决策

| 决策 | 结论 | 原因 |
|---|---|---|
| 模型命名 | `MatchInfo`（table=`matches`） | `match` 是 PHP 8 保留字，写 ADR-001 |
| 双方阵容 | matches 表 `lineup_home/lineup_away` 两个 JSON 字段 | 需求无球员库，避免过度设计 |
| 比分口径 | `home_score/away_score` 为冗余，真源是 match_events 中 goal 聚合；事件增删改同事务回写 | 保证"比分=进球数"一致性 |
| 防重复提交 | `match_events.client_token` 唯一索引（前端 UUID），冲突→40009 | 双击/重试安全 |
| 文件存储 | 三类赛事文件走 local 私有 disk + 鉴权下载接口；队伍 Logo 等公开素材走 public disk | 匿名不可访问私有文件，写 ADR-002 |
| 人脸核验 | `FaceVerifyClient` 接口 + `MockFaceVerifyClient` + config driver=mock，容器绑定 | 契约先行，替换第三方零业务改动 |
| 直播刷新 | 前端 10s 轮询 + since_id 增量；详情缓存 TTL 10s 与轮询同节拍 | 不上 WebSocket |

## 二、数据库迁移（5 表）

**matches**：id；group_type(university/middle_school/primary_school)；home_team_name/away_team_name；home_team_logo/away_team_logo nullable；match_time；venue nullable；status(not_started/live/finished, 默认 not_started)；home_score/away_score smallint 默认 0；lineup_home/lineup_away json nullable；live_link varchar(512) nullable；version int 默认 0；created_by/updated_by；timestamps+softDeletes。索引：(group_type,status,match_time)、(status,match_time)。

**match_referees**：id；match_id FK cascade；role(chief/assistant/fourth)；name。唯一 (match_id,role,name)。

**match_events**：id；match_id FK cascade；type(goal/yellow/red/substitution/text)；minute tinyint；team_side(home/away) nullable；player_name/player_no nullable；related_player_name nullable（助攻/换上）；content varchar(500) nullable；client_token varchar(64) UNIQUE；created_by；timestamps。索引：(match_id,type)（榜单聚合）、(match_id,minute,id)（时间轴排序）。

**match_files**：id；match_id FK cascade；type(sign_in/record_confirm/referee_report)；file_name；file_path（私有 disk）；mime；size；uploaded_by；created_at。索引 (match_id,type)。

**face_verify_records**：id；match_id FK cascade；player_name；player_no nullable；photo_path nullable；result(pass/fail/pending)；score decimal(5,2) nullable；channel 默认 'mock'；request_id nullable；remark nullable；created_by/created_at。

## 四、Service 层职责（[T]事务 [L]business日志 [C]缓存失效）

- **LiveQueryService**：paginateMatches（live 走缓存）、getMatchDetail（TTL 10s，未找到→ModelNotFound）、getEventsSince（since_id 增量，最小字段）。
- **MatchService**：create [L]；update/delete/changeStatus/updateLineup 均 [T][L][C]——`where id+version` 条件更新影响 0 行→BusinessException(9)；finished 后禁改→40002；状态 before/after 记日志；缓存 forget（DB::afterCommit）。
- **MatchEventService**（事务核心）：addEvent [T][L][C]——lockForUpdate 取比赛→finished 抛 40002→client_token 唯一冲突抛 40009→插事件→goal 按 team_side 锁内 increment 比分且 version+1→日志记事件+比分 before/after；updateEvent 涉及归属变化先回退再重算；deleteEvent goal 比分 -1。事务内禁任何 HTTP/文件 IO。
- **RefereeService**：replaceForMatch [T][L]（角色数量校验后 delete+insert）。
- **MatchFileService**：校验在 FormRequest；文件落盘在事务外；download 鉴权流式输出；delete 删库+删物理文件（删文件失败仅记 exception 不回滚）[L]。
- **LiveLinkService**：updateLink [L][C]，finished 40002。
- **FaceVerifyService**：verify——存照片→调 FaceVerifyClient（3s 超时，超时→BusinessException 50008）→落库（channel/request_id/score）[L]；paginateRecords。
- 缓存失效约定：`live:detail:{id}` 精确 forget；列表用 Redis tag `live:list` 批量失效，禁通配扫描。

## 五、前端拆分与 composables

- 超 600 行预拆：MatchListView（SearchForm/Table/FormDialog 三组件，FormDialog 含阵容再拆 LineupEditor）；EventManagePanel（EventTable + EventFormDialog 按 type 动态显隐字段）。
- useLivePolling(matchId)：10s setInterval + since_id 增量；visibilitychange 隐藏暂停/显示即刷；onUnmounted 清理；finished 自动停。
- useEventActions：add 时 crypto.randomUUID() 作 client_token；40009 提示"请勿重复提交"不重发；成功用返回值局部更新比分。
- axios 拦截器：code≠0 按段位 toast（40002/40009 业务提示、20001 跳登录、90001 通用+trace_id）。
- 弹窗重开 resetFields；搜索输入 300ms 防抖；admin 按钮 v-permission。

## 七、冒烟测试（scripts/smoke_test.py，Python+requests）

`check(name, cond)` 累计，失败退出码非零。覆盖：
1. 登录（错误密码→20001）；响应五字段+trace_id UUID 格式。
2. 比赛生命周期：创建→缺字段 10001→旧 version PUT→9→start→公众列表可见→**3 个 goal 后比分 2:1 且等于事件聚合**→删一个 goal 比分回退→同 client_token→40009→finish→再录事件 40002→PUT 40002；live/finished 删比赛→40002，not_started 可删。
3. 裁判：chief×2→10001；合法组合→0。
4. 文件：伪格式→10006；超大→10007；合法上传→带 token 下载 200+Content-Disposition→删除后下载→30001。
5. 链接：非法 URL→10001；合法→公众详情一致。
6. 人脸：mock pass 落库；超时开关→50008；records 可见。
7. 分页：60 场比赛分 3 页无重复遗漏；列表响应不含 lineup 大字段。
8. 服务端 storage/logs 三通道日志文件当日有新增（本地直读）。

## 八、风险与对策

- PHP `match` 保留字→模型名 MatchInfo（ADR-001）
- 人脸第三方未到位→接口+Mock+config driver，channel/request_id 字段预留（ADR-002 同文件存储决策）
- 比分不一致→锁内聚合回写+client_token 唯一索引+version 乐观锁+冒烟兜底；备 artisan `match:recalc-score` 对账命令
- 轮询压力→详情 10s 缓存、事件增量+200 条上限、live 列表 30s 缓存
- 同 minute 顺序→排序键 (minute,id)，前端按返回序渲染
- 事务内 IO→文件落盘/人脸调用均在事务外，列入 CR 检查
- 事件条件校验复杂→required_if:type,goal + after 钩子集中校验

## 验证方式
